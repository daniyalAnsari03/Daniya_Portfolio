SERVER CONTRACT (from route.ts)
POST /api/chat with JSON { message: string (1-500 chars), sessionId?: uuid }. The client sends ONLY the new message plus the sessionId; it never sends history or roles.
Responses:
- 200 text/event-stream. Events `data: <json>\n\n`: {type:"session", sessionId}, {type:"delta", text} (text chunks may split in the middle of a word, e.g. "D","ani","yal"), {type:"done"}, {type:"error", code:"server_error"|"empty"}. Comment lines ": ping" must be ignored.
- 429 JSON {error:"rate_limited", retryAfterSeconds}, 400 invalid_request, 403, 413, 415, 500.

PART B — Word queue and animation (the core of this step)
Pipeline: SSE delta text -> a text buffer -> complete words -> a word queue -> released one word at a time on a timer -> rendered.
1. Splitting: append each delta to a buffer. Only move COMPLETE words to the queue: a word is complete when followed by whitespace; keep the unfinished tail in the buffer. When "done" arrives, flush the tail as the last word. Preserve structure: "\n\n" becomes a paragraph break token, a single "\n" a line-break token, and a line starting with "- " a list item. Break tokens are released instantly (no delay), they are not words.
2. Release pace: a base value WORD_INTERVAL_MS (start 70) from the shared motion tokens. Use a timer based on requestAnimationFrame or setTimeout with timestamps so the pace is steady even if the tab lags. If the queue is long (over about 40 words), speed up gently and smoothly (for example scale the interval down to a floor of about 25 ms as the queue grows) so the user never waits long, and return to the normal pace when the queue shrinks. The pace must stay smooth when the server is fast or stalls.
3. Rendering: each released word is its own span with a stable key (its index in the answer), fading in with opacity 0 -> 1 and translateY of a few px -> 0, using ONLY opacity and transform, duration from a token (start about 450 ms, ease from the existing tokens). Already shown words never re-animate or re-mount. Reduced motion (prefers-reduced-motion): opacity only, no translate.
4. Markdown while streaming: only simple structure: paragraphs, plain "- " lists, and nothing else (no headings, no bold, no code). Render lists and paragraphs from the break tokens so half-built formatting never jumps. Do not use a markdown library for the streaming view.
5. Finish: when the stream is done AND the queue is empty, collapse the word spans into plain text (for mobile performance), keeping the same visual result with no layout jump. Then fade in the existing speaker and copy buttons under that answer. Copy must copy the clean plain text of the answer.
6. Thinking indicator: show the existing thinking logo from the moment the user sends until the FIRST word is released (not until the first delta arrives), then remove it. The header logo breathes only while a reply is pending (until done).
7. Auto-scroll: keep the chat scrolled to the bottom while words appear, but only until the user scrolls up by hand; if they scroll back near the bottom, resume. Do not fight the user's scroll.
8. Abort/cleanup: New chat, closing the drawer, route change and unmount abort the request, clear the timers and the queue. Starting a new message while one is streaming is blocked (disable Send, like the thinking state does today). No state updates after unmount.
9. Performance: one timer for the whole answer (not one per word), will-change only on the currently animating spans, and remove it when they finish.
